# Contributing to Skriptium

First off, thank you for considering to help out!

## How You Can Help
You don't have to be a pro coder to contribute! Here are a few ways to help:
- **Syntax Ideas:** Have a better way to handle a specific Skript feature? Open an issue and suggest it!
- **Testing:** Once the beta is live, help me find bugs by intentionally trying to break the language.
- **Coding:** Help implement the parser or port the modules (addons).

## The Contribution Process (For Developers)

To keep the project stable, we use a branching system. Please follow these steps:

### 1. Fork & Branch
- **Fork** this repository to your own account.
- Create a new branch for your feature (e.g., `feature/add-variables` or `fix/bug-123`). 
- **Do not** push directly to the `main` branch.

### 2. Code & Commit
- Make your changes.
- Keep your commit messages clear (e.g., *"Added support for if/else blocks in JS style"*).

### 3. The Pull Request (PR)
When you are happy with your changes:
- Open a **Pull Request**.
- Target the `beta` branch first. This allows us to test the new feature without breaking the stable `main` version.
- Describe what you changed and why.

### 4. Review & Merge
- Once the PR is reviewed and tested in `beta`, it will eventually be merged into `main` during the next official update.

## Project Guidelines
- **Read the Specs:** Before adding a feature, check `specifications.md` to make sure it fits the Skriptium logic.
- **Be Kind:** We are all learning here. Be helpful and patient with others.
- **Simplicity First:** If a feature makes the language too complicated, we might decide not to include it.

**Happy Coding!**
